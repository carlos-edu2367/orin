# Orin `v0.13.3` — Notas de Versão

**Data:** 2026-11-23  
**Migrações Alembic:** nenhuma

---

## Correção: chamada de ferramenta escrita como texto pelo modelo

Na `0.13.2` o Orin passou a esconder da tela uma chamada de ferramenta que o modelo escreveu como texto (`<invoke name="Bash">`, `</function_results>`) em vez de chamar a ferramenta. A `0.13.3` ataca a causa provável e fecha os caminhos que ainda deixavam o texto cru passar.

1. **Histórico reidratado sem sintaxe de chamada (turnos nativos de Claude, Codex e Antigravity):**
   - Ao reabrir uma sessão do CLI, o Orin reenviava o histórico com cada chamada antiga escrita como texto (`[Tool Use id=… name=…]{json}[/Tool Use]`). Numa conversa longa o modelo via dezenas delas, imitava o padrão e escrevia a próxima chamada como texto, que não executa nada.
   - Agora cada chamada antiga vira um registro no passado, que não se parece com sintaxe de chamada: `(Orin log: the assistant used tool Bash (call id=call_1); arguments: command="pytest -q")`. O histórico abre com um cabeçalho fixo dizendo que aquilo é um registro e não um formato a copiar.
   - A compactação e o corte por orçamento reconhecem o formato novo e o antigo.

2. **Aviso fixo ao modelo:** o prompt estável dos três CLIs ganhou uma regra curta: só as ferramentas do Orin expostas pelo mecanismo nativo são executadas; ferramentas próprias do CLI fora dessa lista não rodam, e texto que imita uma chamada nunca produz resultado. O texto é o mesmo em todo turno, para não quebrar o cache de prompt. A mensagem de correção enviada ao modelo repete a regra.

3. **Saneamento único antes de gravar:**
   - Uma única função (`sanitize_assistant_text`) limpa o texto do assistente em todos os caminhos: turno nativo, protocolo de texto, laço clássico de Codex e Antigravity, subagentes, gravação final da mensagem, Discord, e copiar/exportar na interface.
   - Um teste de contrato falha se surgir um novo ponto de gravação do texto do assistente sem passar por ela.
   - Backend e frontend leem o mesmo arquivo de casos (`tests/fixtures/text_tool_leak_cases.json`), para as duas regras não divergirem.

4. **Texto legítimo preservado:**
   - Uma tag citada em código inline (entre crases) ou em bloco de código nunca é removida.
   - Um bloco aberto e não fechado só é removido até o fim quando começa uma linha; uma tag solta no meio de uma frase fica no texto.
   - O parser do protocolo de texto não trata mais uma tag citada como chamada real nem como resultado inventado. O mesmo vale para o provedor OpenCode.

---

## Limites conhecidos
- Escrever a chamada como texto é comportamento do modelo; a correção reduz a chance e garante que nada apareça cru nem se perca, mas não a elimina.
- Não houve teste com um CLI real numa conversa longa; a confirmação vem do uso.
