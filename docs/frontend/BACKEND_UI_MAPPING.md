# Backend → UI Mapping

> Revisado na Fase 6 (IMPLEMENTATION_PLAN.md) contra o código atual do frontend
> (`frontend/src`) e do gateway (`src/agentos/api/gateway.py`,
> `src/agentos/bootstrap/production.py`), não apenas contra a versão anterior deste
> documento. Hipóteses que a implementação das Fases 1–5 já contradisse foram
> corrigidas nas linhas abaixo; as demais permanecem como estavam.

| Backend entity/event | Endpoint/event real | Significado | Projeção/UI | Gatilho de motion | Fallback/limitação |
| --- | --- | --- | --- | --- | --- |
| Execution create | `POST /v1/executions` | Intenção aceita, recibo `202` (`_receipt`: `outcome`, `execution_id`, `state_version`) | `Home` composer → navegação para `/execution/{id}` → `ExecutionRoute` | Nenhum morph compartilhado: Home e Execution são rotas distintas sem `layoutId` em comum; a transição é a troca de rota do React Router, não uma animação de layout. | Sem prompt livre; `agent_id`/`task_ref` são os únicos campos aceitos pelo composer. |
| Execution state | `GET /v1/executions/{id}` + `POST /v1/events/streams` + `.../read` | Lifecycle versionado (`state`, `state_version`) | `ExecutionRoute`/`ExecutionRealtimeStore`: status label, `ExecutionControls` e `activity-block` | crossfade de label (`StatusLabel`), halo (`.agent-orb`) | Composto em produção pela Fase 0 (`PostgresSecurityService`, `ExecutionApplicationAdapter`, `ExecutionQueryAdapter`, `PostgresClientEventStream`). Recursos sem DTO público continuam fail-closed. |
| `ExecutionWaitingForUser` | evento de lifecycle no stream + `POST /v1/executions/{id}/input` | input é necessário; o domínio volta a `QUEUED` após anexar a referência | `toVisualStatus` mostra "Aguardando você" e `ExecutionInputComposer` abre um `Disclosure` para enviar a referência | nenhum (apenas o crossfade de label já coberto acima) | O composer envia somente `{ input_ref, expected_state_version }` e espera o snapshot/stream; não existe campo de texto nem resolução autorizada para input. |
| `ToolStarted/Progressed/Finished` | Tool Runtime outbox, agora com ponte durável até o `ClientEventStream` (`PostgresToolActivitySink`, ver `docs/frontend/IMPLEMENTATION_PLAN.md` Fase B) | invocation | `ToolActivityGroup` por `invocation_id`, quando `events` está disponível | expand/collapse (`ActivityGroup`), progresso por contagem de `ToolProgressed` observados (nunca percentual) | Implementado como normalizer/componente puro contra o payload assumido; a ponte outbox→SSE existe e está provada por teste de integração contra Postgres real, mas **nenhuma rota HTTP compõe um `ToolRuntimeService` com esse sink** hoje — `ExecutionRoute` continua sem popular `events` a partir de um binding real; só a rota de fixture `/execution/fixture-collaborating` exercita esse caminho. |
| `DelegationCreated` | Multi-agent event, agora com ponte durável até o `ClientEventStream` (`PostgresMultiAgentEventRecorder`, ver `docs/frontend/IMPLEMENTATION_PLAN.md` Fase B) | child ligado a parent | `AgentRail`/`OrchestrationScene`: aresta `delegation` | pulso único nos dois nós ao observar a aresta pela primeira vez (nunca no mount inicial nem em replay) | O payload assumido pelo frontend (`delegation_id`, `child_execution_id`, `child_agent_id?` — IMPLEMENTATION_PLAN.md, Fase 4) é agora produzido de fato pelo projetor da Fase B (traduzindo os campos do envelope de domínio); mas **nenhuma rota HTTP compõe um `MultiAgentCoordinatorService`** hoje, então nenhum evento real chega à tabela fora de um teste. |
| `StructuredHandoffCreated` | Multi-agent event | handoff existente | **não projetado** | nenhum | Não consumido por `agentGraphProjection`; nenhuma UI depende deste evento hoje. |
| `DelegationResultReturned` | Multi-agent event, mesma ponte durável do `DelegationCreated` acima | resultado retornou | aresta `result` (child → parent), correlacionada por `delegation_id` | pulso único child→parent | Resultado é ref, não texto; mesma limitação de composição (nenhum coordinator real em produção) do `DelegationCreated`. |
| `AgentWait*` | Multi-agent event, mesma ponte durável do `DelegationCreated` acima | parent espera/retoma | `AgentNode.visualState = 'waiting'`, distinto de `PAUSED` manual | anel muda de estilo por `data-state` (CSS estático, sem loop contínuo) | Mesma limitação de composição (nenhum coordinator real em produção); a UI nunca infere espera a partir de `PAUSED`. |
| Provider config | `PUT/GET/DELETE /v1/providers/{provider}` | conexão segura | `ProviderSettingsPage`/`ProviderPanel` | transição textual de status (`describeState`) | **Composto em produção** (`PostgresProviderConfigurationAdapter`, ver `docs/frontend/IMPLEMENTATION_PLAN.md` Fase D) — `PUT`/`GET`/`DELETE` funcionam fim a fim contra Postgres real. A chave nunca é relida/reexibida (nem pela API, nem por armazenamento de resposta); permanece armazenada em texto plano no banco (sem criptografia de campo — mesma limitação que `ProductionSettings.OPENAI_API_KEY`/etc. já tinham, ver "Decisões locais" da Fase D). |
| Artifact/Memory/Workspace | `GET /v1/{artifacts,memories,workspaces}` genérico | snapshot autorizado | **nenhuma aba de inspector criada** | nenhum | `BACKEND_DISCOVERY.md` continua sem confirmar schema/paginação; criar uma aba exigiria inventar um DTO (proibido). Gap mantido na Fase 6 na mesma prioridade P2 de `BACKEND_CAPABILITY_MATRIX.md`. |
| Erro público | envelope `{ error: { code, category, message_key, correlation_id, retryable, retry_after } }` | falha sanitizada | Aviso inline `role="alert"` no ponto de origem da ação (`ExecutionRoute`'s `sr-alert`, `ProviderErrorNotice`) — **nunca** um toast global | nenhuma animação distintiva; texto de prazo (`retry_after`) e `correlation_id` aparecem quando o envelope os fornece | Categorias efetivamente levantadas hoje por `src/agentos/api/gateway.py` (`@app.exception_handler`): `VALIDATION` (422, `RequestValidationError`), `AUTHENTICATION` (401), `AUTHORIZATION` (403, tanto `AuthorizationError` quanto `PermissionError`), `RATE_LIMITED` (429, com `retry_after=60` fixo), `INTERNAL` (500, catch-all). `CONFLICT` e `INDETERMINATE` são categorias que `api/errors.ts` (`shouldResync`) já sabe interpretar e disparam ressincronização na UI, mas **nenhum adapter deste gateway as levanta hoje** — são cobertas nos testes desta fase (`execution-controls.spec.ts`) por um fake explicitamente documentado como tal, não por um contrato de produção comprovado. |
# Provider/model composer (2026-08-10)

| UI | Contrato | Regra de segurança |
| --- | --- | --- |
| Home / Mensagem | `POST /v1/conversations` | Não renderiza nem envia `agent_id` ou `task_ref`. |
| Provider e modelo | `GET /v1/providers/{provider}/models` | Só modelos do cache autorizado do usuário; IDs são qualificados pelo provider. |
| Atualizar catálogo | `POST .../models:refresh` | Chave fica no servidor; mantém o último cache quando o upstream falha. |
| Favorito | `PUT/DELETE .../favorites/{model_id}` | Preferência por `(usuário, provider, model_id)`, não altera credencial. |
