# Release v0.2.3

## Conteúdo

- Biblioteca de plugins: busca (GitHub keyless), abas Instalados/Biblioteca, instalação a partir de repositórios sem manifesto com inferência de comando MCP.
- Comandos de plugin: parsing, contribuição, ativação, expansão no prompt do turno, e um seletor de comandos no composer.
- Hooks de plugin: parsing, contribuição, execução confinada com timeout, despacho de eventos de ciclo de vida (SessionStart, PostToolUse, PostCompact) atrás de um consentimento explícito separado da instalação.
- Servidores MCP declarados inline no manifesto do plugin, com card de aprovação, chip do comando invocado na transcrição, e o fallback "instalar como MCP" a partir da Biblioteca.
- Três correções de ativação de MCP no Windows, encontradas instalando o plugin de referência obsidian-second-brain de ponta a ponta:
  - `${CLAUDE_PLUGIN_ROOT}` agora é resolvido no comando/args do MCP antes de propor o servidor (antes, o `$` literal era recusado como metacaractere de shell).
  - A guarda de metacaracteres de shell (`<>^%`) agora vale só para launchers que viram shim `.cmd`/`.bat` no Windows (`npx`); launchers nativos (uv/uvx, node, python, deno, bun) não passam por cmd.exe, então um pin de versão como `mcp<2` deixou de ser recusado.
  - O ambiente do processo filho passou a herdar `TEMP`/`TMP`/`USERPROFILE`/`APPDATA`/`LOCALAPPDATA` (Windows) ou `HOME`/`TMPDIR` (POSIX) além de `PATH`; sem isso, `uv` caía num diretório temporário sem permissão de escrita e o servidor morria antes de responder ao handshake.
- Teste de versão do launcher deixou de fixar um literal (`"0.2.1"`) que já estava desatualizado; agora compara só contra `__version__`.
