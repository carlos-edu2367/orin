# Release v0.2.13 — economia de tokens do runtime agêntico

Data: 2026-08-28 · Base: `v0.2.12`

## O que muda

Nada no comportamento visível. Esta release trata do custo: o Orin passa a reaproveitar o cache de prompt do provider em vez de invalidá-lo a cada iteração, e para de reexecutar leituras que ele mesmo acabou de fazer.

## O achado

`_age_tool_results` rodava depois de cada requisição e encolhia, no lugar, o resultado de ferramenta recém-enviado. Na iteração seguinte aquela mensagem — no meio do prefixo — tinha bytes diferentes, então a entrada de cache gravada já nascia inválida. Medido com seis chamadas de ferramenta, o prefixo compartilhado era sempre exatamente `len(anterior) − 1`: **toda escrita de cache era desperdiçada**.

A compressão também era uma economia falsa. Um token lido de cache custa cerca de um décimo de um token de input comum, então cortar um resultado de 12k para 400 caracteres economizava ~2.900 tokens a preço cheio enquanto invalidava um prefixo que, dez passos adiante, já passava de 30.000 tokens que teriam custado um décimo.

## O que foi feito

- **Prefixo append-only.** O encolhimento passou para dentro da compactação, que já reescreve o prefixo inteiro e é, portanto, o único lugar onde isso é de graça. Entre compactações, a lista de mensagens só cresce.
- **Prompt em duas camadas.** O bloco de system cacheável carregava a árvore do workspace, o ledger, as skills recuperadas e a data — praticamente nunca se repetia entre turnos. Agora o estável e o volátil viajam separados.
- **Dois breakpoints de mensagem** em vez de um. A cauda sozinha para de casar assim que a próxima mensagem é anexada; o segundo fica na última mensagem da unidade anterior, que a requisição seguinte ainda compartilha.
- **Leitura repetida servida do turno**, quando a ferramenta é somente-leitura e nenhuma escrita ocorreu no meio.
- **Providers sem cache** mantêm exatamente o comportamento anterior: sem cache para proteger, encolher é puro ganho.

## O que esta release não faz

- `cached_fraction` real, cobrado por um provider, continua sem número. As medições acima são do prefixo e do prompt, não da fatura: produzir o número exige credencial e é passo do operador (`scripts/agent_bench.py`).
- `run_command` não é deduplicado, mesmo quando o comando apenas lê. O runtime não tem como saber se um comando escreve, e adivinhar teria consequência de correção.
- Trilha C (evidência obrigatória antes de declarar conclusão, subagentes estruturados) permanece pendente.
