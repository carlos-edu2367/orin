## Summary verdict

**Not ready for W4.** The building blocks are sound and well tested: one reminder mechanism with tag neutralization, repository settings that can only lower `maxTurns`/`maxBudgetUsd`/`safetyMaxToolRounds`, the five operator-only keys really are never read from a repository, `git status` only in trusted workspaces with fsmonitor off, durable lease renewal that keeps long Code turns alive while still recovering abandoned ones, atomic queue claims with ownership checks, a delta guard after cancel, a `max_tokens` recovery that never runs a cut tool call, and a full suite that is green. But three defects break what W3 promises, and a group of medium ones undermine its loop and trust guarantees:

1. **Every automatic compaction silently drops the most recent exchanges from the next turn.** The compaction keeps the newest 6 units verbatim in memory, but the persisted `compact_boundary` covers everything before the current request, so on the next turn those units are neither in the summary nor in the history. (R1)
2. **An untrusted repository makes Orin open an attacker's SMB share on every turn.** `@//host/share/x.md` in a repository `CLAUDE.md`/`AGENTS.md` is rejected as "outside the project", but only after `Path.resolve()` has opened the UNC path (NTLM challenge/response on Windows; a 22 s stall when the host does not answer). (R2)
3. **A ConfigChange refusal is not fail-closed.** The refused settings' hooks are installed and run (UserPromptSubmit, InstructionsLoaded, SessionStart) in the "blocked" turn and every following one; only the model call is skipped. (R3)

Medium: an untrusted repository can strip the user's own `CLAUDE.md`/`ORIN.md` (R4) and force a summarizer call on almost every request (R9); queued text auto-answers an `ask_user` question and auto-continues past the safety pause (R5) and is not durable (R11); a fallback switch keeps the primary's effort and prices (R6); Code-mode subagents keep the 1 h deadline and are outside `maxBudgetUsd` (R7); SessionEnd never runs on a normal Orin stop (R8); a cancel does not stop the running tool (R10); effort overrides an explicit output cap (R12, self-reported); and edits to instruction files are invisible to the model until the next compaction, while InstructionsLoaded reports them every turn (R13).

All seven items the executors reported themselves were reproduced (R12, R20, R21, R23, R26, R29, and the FileChanged cost in R19).
