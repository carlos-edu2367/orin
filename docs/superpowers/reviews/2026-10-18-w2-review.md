# W2 Hooks: adversarial review

- Scope: `git diff 598135a..HEAD` (11 commits, `9e7dfb0` to `bde7f8f`) on `feat/orin-code-parity-w0-w3`.
- Reviewed against: `docs/superpowers/plans/2026-10-18-w2-hooks.md` (incl. its Deviations), the ledger `2026-10-18-w2-hooks-ledger.md` (7 implementer deviations + the agent-hook recursion fix), master spec §5 (and §4.5, §14), the REA notes in `claude-re-specs/03-...md` §2, and the W1 review.
- Method: read every changed line, then attacked process control, config/trust, protocol, runners, dispatcher and the toolset/runtime/session application with throwaway scripts kept outside the repo. Every process I spawned or terminated was my own; the PID-walk hazard was shown **read-only** (the function was called and its return value printed, nothing was killed).

## Summary verdict

**Not ready for W3.** The shape is right: hooks load from the 5 layers, untrusted repository files drop `hooks`, payloads go to command hooks only through stdin (no shell interpolation of event data), the PreToolUse `updatedInput` path is re-checked by the permission engine (a managed `deny` still wins), plan mode cannot be bypassed by a hook `allow`, the Stop continuation loop is bounded (5) and keeps a coherent transcript, the agent-hook recursion guard holds, plugin hooks still run on their own path (no double execution), and with no hooks configured nothing is subscribed. The suite is green (numbers below).

The problems are at the edges where a hook decision touches security, and in process control:

1. **The Windows process-tree "fix" can kill the user's desktop, and Orin itself.** `_windows_descendants` trusts `th32ParentProcessID`, which Windows never clears: on this machine 21 live processes point at a dead (reusable) parent PID. If a hook shell receives one of those PIDs and times out, `_kill_tree` terminates that orphan and its whole subtree; for one of them this is `explorer.exe` plus 148 descendants, Orin's own process included. The underlying diagnosis in Deviation 1 is also wrong: the Job Object works. What escapes it is the **Microsoft Store (MSIX) Python** used on this machine (a packaged app starts outside its caller's job). `cmd`, `powershell` and `ping` grandchildren are all captured and killed by `TerminateJobObject`. (R1)
2. **An untrusted workspace runs its hooks when its `.claude`/`.orin` is a junction or symlink** to a directory outside the root, e.g. `packages/app/.claude -> ../../tooling/cfg` in a monorepo clone. `_inside()` resolves the link, decides the file is "not in the repo", and skips the trust filter. That is code execution on the first turn (SessionStart) with no trust card. W1 left this as a low residual; W2 turns it into code execution. (R2)
3. **An untrusted repo silently disables every managed and user hook** with `disableAllHooks: true`: it is a "restriction" the loader accepts before trust, and `load_hook_specs` honours it for every layer. Organisation guard hooks and the user's own secret-scanner stop running, and no trust card is shown. (R3)
4. **A PermissionRequest `allow` with `updatedInput` skips the permission engine.** A managed `deny Bash(del:*)` was bypassed and `del victim.txt` ran. (R4)
5. **A PreToolUse `allow` turns even `requires_human` asks into allow.** With `updatedInput` it can retarget an innocent write to `.git/hooks/pre-commit` or `.orin/settings.json` in acceptEdits. This contradicts spec §4.5 ("protected paths always ask"). (R5)
6. **A prompt blocked by UserPromptSubmit is not erased.** It stays in the conversation history and goes to the model on the next turn. Before the block is honoured, it is also expanded for `@` mentions, used for memory ranking, and written into `.orin/plans/<turn>-plan.md` in plan mode. The canonical use of this hook (refuse a prompt that contains a secret) is defeated. (R6)

R1–R6 must be fixed before W3. R7 (prompt/agent verdict ambiguity fails open) and R8 (timed-out agent verifiers keep running and silently disable later agent hooks) are small, security-relevant and should be fixed in the same pass.

## Must fix before W3

- **W2-R1** (critical) — Windows tree kill trusts stale parent PIDs and can kill `explorer.exe`/Orin; validate by creation time and handles, drop `taskkill /T`, correct the Deviation 1 diagnosis (Store/MSIX Python escapes the job).
- **W2-R2** (high) — `.claude`/`.orin` junction or symlink escaping the workspace skips the trust filter → untrusted hooks run.
- **W2-R3** (high) — untrusted repo `disableAllHooks: true` disables managed and user hooks; compute per layer, never let non-managed disable managed.
- **W2-R4** (high) — PermissionRequest `allow` + `updatedInput` skips the permission engine (managed deny bypassed).
- **W2-R5** (med-high) — PreToolUse `allow` converts `requires_human` asks (protected paths, ask rules) into allow.
- **W2-R6** (high) — a prompt blocked by UserPromptSubmit stays in history and is used (mentions, memory, plan scaffold) before the block.
- **W2-R7** (med) — disagreeing prompt/agent verdicts fail open; fail closed on any `ok:false`.
- **W2-R8** (med) — timed-out agent/prompt hooks keep running, leak threads and disable later agent hooks; dispatchers never closed.
- **W2-R9** (med) — unbounded hook stdout/stderr and HTTP body buffering.
