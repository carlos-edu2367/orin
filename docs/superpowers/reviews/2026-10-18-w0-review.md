# W0 Foundations: adversarial review

- Scope: `git diff f77aeb7..HEAD` (10 commits, `5b54794` to `0a252d6`) on `feat/orin-code-parity-w0-w3`.
- Reviewed against: `docs/superpowers/plans/2026-10-18-w0-foundations.md` (including its Deviations), `2026-10-18-w0-foundations-ledger.md`, and master spec sections 3, 5.4, 13, 14 and 16.
- Method: read every changed line, then attacked the code with throwaway scripts kept outside the repo (translator through the real runtime, settings loader and writer, multi-process writer contention, parallel tool pool).

## Summary verdict

**Not ready for W1. W0 needs one fix batch first.** The structure is sound. The translator round-trips correctly for every tool that has a public schema, including Anthropic `tool_use` blocks. The 5-layer precedence is correct, and the bus is thread-safe and isolates failing subscribers. Writes from six processes, 40 rules each, lost nothing on Windows.

Three things block W1:

1. **Model output can crash the turn, even with the flag off.** A value the model chooses (`timeout: "--5"`, `"²"`, a 5000-digit string, `10**400`, `options: 5`) raises `ValueError`, `TypeError` or `OverflowError` out of `AgenticTurnRuntime.run`. `TurnSession` always attaches a bus, and `AgentToolset.invoke` builds the hook payload outside any `try`, so this also happens with `experimental.claudeToolNames` off. That is a regression against the W0 rule "no behaviour change when the flag is off".
2. **A repository can make the settings loader raise, and the session then drops every layer.** One `.claude/settings.json` with invalid UTF-8, UTF-16, or deep nesting is enough. `TurnSession.build_runtime` then falls back to `empty_settings()`, which silently discards the managed and user layers (fail-open).
3. **Repository content is trusted.** Repo settings load with `trusted=True` and can set `experimental.*`. Repo settings can also clear the user's restrictions with `null`, `0`, `"false"` or `{}`.

None of this can be exploited through permissions *today*: W0 reads only `experimental.claudeToolNames`. But W1 starts reading permissions from this loader, so these must be fixed before W1 builds on it.

Test results I observed:

- `uv run pytest -q tests/unit/settings tests/unit/agentic`: **683 passed, 2 skipped** (25 s).
- `uv run pytest -q tests/unit`: **2465 passed, 49 skipped, 31 warnings** (166.8 s). That is the 2393 baseline plus 72 new tests. All green, deterministic on Windows.

## Tests assessment

They cover the round trip, idempotency of internal input, precedence, project filtering, change detection, concurrent writer threads, subscriber isolation and every emission site. - **Weak spots:**
  - `watcher._snapshots` is process-global and is not reset by an autouse fixture; this is safe today only because the keys are distinct tmp paths.
  - `test_concurrent_writers_do_not_lose_updates` uses threads, which are serialised by `_process_lock`, so the cross-process file lock is never exercised.
