# Agent Domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar o domínio Agent da RFC 201 com identidade versionada, resolução autorizada, administração idempotente, snapshots imutáveis, Events mínimos e compatibilidade retroativa com o Kernel existente.

**Architecture:** `agentos.agents` será um pacote síncrono e independente de infraestrutura. Modelos congelados e segurança ficam separados das Protocols; adapters em memória coordenam registry, persistência, Execution administrativa, resolução e outbox. `compat.py` traduz apenas referências públicas para Execution, Context, Providers e Events.

**Tech Stack:** Python 3.13+, dataclasses congeladas/slotted, `typing.Protocol`, `enum.StrEnum`, `hashlib`, `datetime`, pytest e somente biblioteca padrão no domínio.

## Global Constraints

- `user_id` é obrigatório em toda identidade, consulta, comando, snapshot, resolução e Event.
- `workspace_id` nulo significa escopo estritamente do usuário, nunca acesso global.
- `ARCHIVED` não possui transição de saída nesta versão.
- Toda mutação que produz trabalho solicita uma Execution administrativa por porta injetada.
- Estado de Agent e outbox do mesmo fato usam a mesma unidade transacional conceitual; o Agent não publica diretamente no bus.
- `COMMITTED`, `NOT_COMMITTED` e `UNKNOWN` são estados distintos; `UNKNOWN` exige inspeção autorizada.
- Mesma chave e fingerprint repetem o resultado; fingerprint diferente produz conflito sanitizado.
- Configurações e snapshots são imutáveis; reconfiguração nunca sobrescreve histórico.
- Prompt, Memory, Tool, Capability, Skill, Provider, Artifact e credenciais aparecem somente como referências públicas/opacas.
- Não adicionar FastAPI, HTTP, SDK de Provider, ORM, banco, Redis, filesystem, broker ou storage concreto.
- Cada comportamento novo seguirá RED observado, GREEN mínimo e refatoração com testes verdes.
