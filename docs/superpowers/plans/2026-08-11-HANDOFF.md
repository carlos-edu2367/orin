Uma auditoria do fluxo de tools do agente conversacional encontrou 22 problemas. Eles foram
organizados em 5 planos executáveis, indexados por

tarefa, um revisor por tarefa (spec + qualidade), rodadas de fix quando o revisor acha algo
Critical/Important, e uma revisão ampla de branch no final.

2. **Tool result órfão.** O laço de empacotamento anda do mais novo para o mais antigo e para no
   primeiro que não cabe. Como tool results são pequenos e a mensagem assistant que carrega as
   chamadas é grande, o laço podia manter o result e cortar a chamada — e **os dois providers
   rejeitam** essa forma (400). O fix agrupa assistant-com-tool-calls + seus results em unidade
   atômica. Verificar as duas formas: OpenAI (`tool_calls` / `role: "tool"`) e Anthropic
   (blocos `tool_use` / blocos `tool_result` sob `role: "user"`).

3. **Edge revelado pelo implementador, a adjudicar:** o marcador de omissão só anuncia o primeiro

A re-review também deve confirmar que o fix não perturbou o que a primeira review já validou:

Depois: dispachar implementador (`general-purpose`, `model: sonnet`) com o caminho do brief e o do

**Convenção de nomes adotada:** `p<N>-task-<M>-brief.md` / `p<N>-task-<M>-report.md` em

**Ledger:** `.superpowers/sdd/progress.md`. É o mapa de recuperação após compactação de contexto.
Tarefas marcadas como completas lá **não devem ser redisparadas**. Atenção: `.superpowers/` está no
`.gitignore` (contém tokens de sessão), então `git clean -fdx` destrói o ledger — recupere de
`git log` se isso acontecer.

## Lições desta execução — leia antes de dispachar

1. **Os planos foram escritos antes do código existir e seus trechos de código contêm bugs reais.**
   Quatro das dez tarefas executadas precisaram de rodada de fix, e em todas o defeito estava no
   código do plano, não em erro do implementador: escape de sandbox por symlink, sufixo de
   truncamento estourando o limite, ordem de execução read/write invertida, pin na mensagem errada,
   tool result órfão. **Diga ao revisor para julgar o código pelo mérito, não pela fidelidade ao
   brief** — o template já faz isso, mas vale reforçar riscos concretos no prompt de review.

2. **Briefs ficam desatualizados conforme as tarefas avançam.** A partir da Task 4 do Plano 2, o
   `_run_toolset` já não era o do brief. Quando isso acontecer, diga explicitamente ao implementador
   o que mudou e que **o comportamento é o requisito, não o trecho literal**. Isso funcionou bem.

3. **Achado "plan-mandated" nem sempre precisa do dono.** Se a correção *implementa* o que o plano já
   declarava (uma constraint global, a prosa do próprio plano, o docstring do método), corrija
   direto. Só leve ao dono quando duas afirmações do plano se contradizem **e** a resolução tem
   trade-off de produto. Nesta execução isso aconteceu uma vez (o limite de 12k), e a decisão foi
   reservar orçamento para o sufixo.

4. **Prompts de review com riscos concretos nomeados acharam bugs; prompts genéricos não.** Nomear
   "verifique se o corte pode órfãozar um tool result" foi o que encontrou o defeito que quebraria
   produção.

## Achados Minor acumulados — insumo para a revisão final de branch

O ledger (`.superpowers/sdd/progress.md`) tem a lista completa com contexto. Os que mais merecem
triagem antes do merge:

- `runtime.py` — `outcomes.get(index) or self.toolset.invoke(...)` é código morto inalcançável;
  trocar por `outcomes[index]` para que uma quebra futura de invariante falhe alto em vez de
  invocar uma tool duas vezes (risco real: `write_file` duplicado).
- `runtime.py` — se `future.result()` levantar, nenhum `tool_finished` é emitido para o lote inteiro,
  perdendo o progresso parcial que o caminho sequencial registrava.
- `agent_tools.py` — o comentário do campo `read_only` diz "no workspace or network side effect", mas
  `fetch_url` faz um GET HTTP.
- `agent_tools.py` — o schema de `depth` fixa `"maximum": 5` em vez de importar `MAX_LIST_DEPTH`.
- `provider_stream.py` — `tool_choice` é convertido para string sem canonicalização; só `"none"` é
  exercitado. Anthropic usa `"any"`, não `"required"`.
- `runtime.py` — `budget_exhausted` fica `True` mesmo quando `max_iterations=1` e a primeira resposta
  foi limpa, o que rotula um subagente bem-sucedido como cortado por orçamento.
- Lacunas de cobertura: duplicatas dentro do mesmo lote não são deduplicadas entre si; sem teste para
  `edits` + `replace_all` juntos; sem teste de clamp de `depth`.
