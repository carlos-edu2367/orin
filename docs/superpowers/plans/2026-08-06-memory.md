# Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the RFC 301 Memory public boundary with a deterministic bounded in-memory adapter, explicit authorization, lifecycle, audit/outbox facts and an optional Context source.

**Architecture:** `agentos.memory.models` owns immutable public contracts; `ports.py` owns the single `MemoryManager` port plus store, search, policy and commit ports; `security.py` owns sanitization and invariants; `in_memory.py` implements the reference manager, store, policy and textual search; `context_compat.py` adapts authorized search matches to the existing `ContextSource` without writing Memory.

**Tech Stack:** Python standard library, frozen/slotted dataclasses, `Protocol`, `StrEnum`, SHA-256 fingerprints, `threading.RLock`, `pytest`; no production dependency beyond existing public Events and Context contracts.

## Global Constraints

- Context remains temporary and no Context operation writes or renews Memory.
- Every sensitive operation carries `user_id`, `workspace_id`, `agent_id`, `execution_id`, `correlation_id`, `purpose` and `actor`.
- Ownership and classification are revalidated before resolution, ranking and materialization.
- All content and results are bounded; references are opaque and contain no physical location.
- Updates use expected versions and never last-write-wins.
- A confirmed mutation atomically includes state, audit and post-commit outbox Event in the reference adapter.
- Events use the canonical `agentos.events.EventEnvelope`; the Memory package does not import concrete persistence, SQLAlchemy, Alembic, Redis, Artifact, Provider, API or broker modules.
- Production durability remains a later composition with the RFC 601 persistence port.
- Preserve all existing working-tree changes; add and commit only the files belonging to this feature.
