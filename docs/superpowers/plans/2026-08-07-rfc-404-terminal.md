# RFC 404 Terminal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a complete, bounded and auditable Terminal Resource behind `agentos.terminal`, integrated with Resource Manager, Workspace/Filesystem, Persistence/Outbox and Artifact references.

**Architecture:** Public frozen models and `TerminalPort` are technology-neutral. `TerminalService` owns session state and authorization orchestration; Resource Manager remains the lease/capability authority; WorkspacePath is the only cwd representation. Reference and local adapters implement the same internal supervisor contract, while persistence/events receive only sanitized snapshots and confirmed facts.

**Tech Stack:** Python 3.13, frozen dataclasses, existing AgentOS ports, deterministic in-memory adapters, optional local `subprocess` boundary, pytest, compileall.

## Global Constraints

- Every operation carries the complete `TerminalOperationContext` and revalidates binding plus lease before effect.
- Public cwd is `WorkspacePath`; physical cwd, native handles, secrets, raw command and integral output never cross public/persistence/event boundaries.
- At most one foreground command is active per session.
- `ResourceManagerService` remains the authority for `TERMINAL` catalog, lease, capability, fencing, expiry, cleanup and quarantine.
- Persistence and outbox use `TransactionalPersistence`; no database, broker, HTTP or ORM is added to the terminal domain.
- Local process execution, when used, is isolated in `terminal/local.py`, uses `shell=False`, allowlisted environment and process-group cleanup.
- New production behavior is introduced only after a failing test has been observed.
