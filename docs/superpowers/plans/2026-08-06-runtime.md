# Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build the reference-only, framework-independent Runtime loop for one AgentOS `Execution`.

**Architecture:** Add a focused `agentos.runtime` package containing public dataclasses, protocols and a Runtime service. Extend the existing `Execution` domain only where required for monotonic public usage and reference-only related changes; all mutations continue through `ExecutionControl`.

**Tech Stack:** Python 3.13+, dataclasses, `Protocol`, `StrEnum`, `pytest`; no runtime dependencies.

## Global Constraints

- Backend Python 3.13+ only.
- Runtime must not import or instantiate FastAPI, Playwright, Redis, SQLAlchemy, AI/provider SDKs, workers, queues or concrete adapters.
- `ExecutionControl` is the only Runtime mutation port for state, usage, result, failure, cancellation and checkpoint association.
- `CheckpointPort` is read-only/recovery-only.
- Runtime payloads contain references and sanitized categories, never secrets or complete sensitive payloads.
- One Runtime instance may govern only one active Execution loop.

        context=command_context,

        idempotency_key="commit-accounting-key-1",
        expected_version=1,
        requested_at=now,
        expected_state=ExecutionState.RUNNING,

            ExecutionRelatedChange(kind="provider-tokens-recorded", reference="tokens:confirmed"),
            ExecutionRelatedChange(kind="checkpoint-recorded", reference="checkpoint:1"),

    assert current.usage.iterations == 1
    assert current.checkpoint_ref == "checkpoint:1"
