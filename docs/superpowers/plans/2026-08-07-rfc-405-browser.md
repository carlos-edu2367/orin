# RFC 405 Browser Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement and verify the complete RFC 405 Browser Resource behind typed boundaries.

**Architecture:** `agentos.browser` separates immutable public contracts, service-side ownership/lifecycle, worker validation, deterministic engine, network policy, input/artifact ports and sanitized persistence/events. Resource Manager remains the authority for BROWSER leases; Browser Worker has no database or general ownership access.

**Tech Stack:** Python 3.13, frozen dataclasses, `StrEnum`, existing AgentOS ports, pytest, optional Playwright boundary.

## Global Constraints

- Playwright executes exclusively behind the Browser Worker boundary.
- Browser Worker does not import or instantiate database, ORM, Redis, state store, Runtime, API or Resource Manager.
- Every sensitive operation carries `user_id`, `workspace_id`, `agent_id`, `execution_id`, `correlation_id`, `purpose` and `actor`.
- Network is deny-by-default and validates initial URL, redirects and resolved destination.
- Public contracts never expose native handles, physical paths, cookie values, storage state, headers or unbounded content.
- DOM, screenshots and downloads become Artifacts only after bounded staging and confirmed commit.
- Existing user changes remain untouched; only Browser files and Gate documentation are staged.
