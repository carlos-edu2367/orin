# Projetos do AgentOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Deliver persistent Projects whose chats share one isolated workspace and project-memory scope while standalone chats retain their current behavior.

**Architecture:** Persist \`projects\` as the owner of a shared \`workspace_id\`, relate conversations through nullable \`project_id\`, and resolve an effective workspace in the chat worker. Extend the durable agent-memory adapter with user/project scope filtering, then expose authenticated APIs and a compact React project navigation.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy/Alembic, PostgreSQL/SQLite tests, React, TypeScript, React Router, Motion, Vitest, Testing Library.

## Global Constraints

- Existing conversations migrate with \`project_id = NULL\` and retain their conversation-derived workspace.
- A project chat's workspace is only \`projects.workspace_id\`; never allocate a replacement during a failed lookup.
- Project and project-memory operations always filter by authenticated \`user_id\`.
- Project memory is bounded and retrieved only for its exact project; standalone never receives it.
- Archiving retains chats, workspace and memory. Moving chats between scopes is deliberately out of scope.
- Preserve streaming, provider selection, skills, tools, agents and subagents.
- Keep the UI minimal, accessible, and reduced-motion safe.
